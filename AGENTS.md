# Инструкции для Codex

Этот репозиторий - личный GitHub Pages-архив, а не один аккуратный продукт.
Перед изменениями относись к нему как к набору независимых мини-проектов.

## Быстрый старт

1. Прочитай `README.md` и `docs/PROJECT_MAP.md`.
2. Проверь `git status --short`: пользователь может держать здесь несвязанные изменения.
3. Используй `rg` / `rg --files` для поиска связей между страницами.
4. Для конкретной папки сначала ищи локальные `README.md`, `PROJECT.md`, `package.json`,
   `.csproj`, `manifest.json` или скрипты запуска.

## Важные принципы

- Не делать массовую уборку без прямой просьбы.
- Не удалять и не перемещать `.exe`, `.zip`, `.gif`, `.mp4`, Unity/WebGL build-файлы,
  кэши данных и старые ассеты только потому, что они выглядят лишними.
- Не переименовывать `.htm` в `.html`: в этом репозитории оба расширения используются
  исторически, и ссылки могут зависеть от точного имени.
- Не считать `node_modules/` случайной ошибкой: местами они уже лежат в репозитории.
- Если меняешь общую библиотеку из `scripts/`, проверь все ссылки на неё.
- Если меняешь публичные страницы, думай про GitHub Pages и относительные пути.
- Если находишь секреты или приватные ключи, не копируй их в новые файлы и не цитируй
  значения в ответе.

## Зоны повышенной осторожности

- `DataList.json`, `TrackAnime/DataList.json`, `PoE/base/*.json` - крупные данные,
  менять только понимая формат потребителей.
- `chatgpt-browser-bridge/` - отдельный проект с собственной документацией и правилами.
- `unity/`, `LoadBundle/`, `vulpera/` - сгенерированные WebGL-сборки, править руками редко.
- `GoogleSheets/` - содержит локальные Node.js файлы и потенциально чувствительные
  Google OAuth артефакты.
- Корневые `.htm` страницы часто являются однофайловыми экспериментами.

## Полезные команды

```powershell
rg --files
rg "some-path-or-function"
git status --short
Get-ChildItem -File | Where-Object { $_.Extension -match '^\\.(htm|html)$' }
Get-ChildItem -Directory
```

## Стиль документации

Пиши коротко и практично. Этот репозиторий полезнее документировать как карту:
что где лежит, как запускать, где опасно трогать, какие файлы являются входами.
